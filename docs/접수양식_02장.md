# 케어드라이브(CareDrive) — 접수양식 02장 (앱 프로젝트 소개)

접수양식 02장에 제출한 본문이다. 대표자·구성원의 이름, 연락처, 소속은 쓰지 않았다. 전체 기획서는 [기획서.md](기획서.md).

앱명 / 프로젝트명: 케어드라이브 (CareDrive)

## 1. 앱 한 줄 소개

부모님의 일상 운전을 감시하지 않고, 평소와 크게 달라진 운전 패턴의 변화를 가족이 놓치지 않게 알려 갈등 없이 건강검진과 인지선별검사로 이어지도록 돕는 가족 안심 차량용 인포테인먼트 앱

## 2. 기획 배경

**초고령 사회 진입과 계속 운전하는 고령자 증가.** 2024년 기준 65세 이상 운전면허 소지자는 약 517만 명(고령 인구의 52%)이지만 면허 자진 반납률은 수년째 2%대에 머물고 있습니다. 고령 운전자 사고도 늘고 있으나(운전자 수 증가 효과 포함), 일방적인 면허 반납 권유는 부모 세대의 이동권 박탈감과 자존감 훼손을 불러 가족 간 대화 단절로 이어집니다.

**3년 적성검사 주기 사이의 '일상 모니터링 공백'.** 75세 이상 고령 운전자는 3년마다 정기 적성검사와 인지선별검사(CIST)를 받지만, 최대 3년이라는 공백기 동안 신체·인지 능력의 변화를 일상에서 알아차릴 장치가 없습니다. 정부는 2026년부터 실차·VR 기반 운전능력 진단 시스템을 시범 운영하고 2027년 조건부 면허 연계를 검토하고 있으나, 그 이전에 '일상 운전의 안전망'이 필요합니다.

**기존 스마트폰 추적 앱의 한계.** 스마트폰 기반 위치 추적 앱은 배터리 방전·미소지 문제뿐 아니라 동승 상황을 운전으로 오인하는 등 데이터 정합성이 떨어집니다. 무엇보다 자녀의 일방적 '실시간 위치 감시'로 인식되어 부모의 거부감이 큽니다. 또한 운전 빈도 감소는 노화·신체 질환(시력·관절)·우울 등 다양한 원인이 섞여 있으므로 치매로 단정해서는 안 되며, 원인별로 분리된 접근이 필요합니다.

**해결하고자 하는 문제.** 부모의 운전 자율성과 프라이버시를 지키면서(실시간 감시 배제, 부모 주권 보장), 차량 고유 센서 데이터로 평소 기준선 대비 '오래 지속되는 큰 변화'를 감지하고, 가족 간 갈등 없이 적절한 검진(종합 건강검진 또는 치매안심센터 선별검사)으로 자연스럽게 이어 주는 서비스가 필요합니다.

## 3. 앱 주요 기능 및 차량 특화 요소

### 1) 시동 기반 기준선 학습과 만성 변화 감지 (만성 채널)

- **시동 연동 트립 확정**: 시동 ON부터 시동 OFF(시동을 끈 시점)까지를 1개 트립으로 기록하고, 시동을 끄는 시점에 차량 안에서 일별 데이터를 정리한 뒤 원시 위치 좌표는 즉시 파기합니다.
- **개인 맞춤형 기준선**: 28일 이상, 트립 20회 이상의 데이터로 부모 본인의 운전 패턴을 기준선으로 고정합니다. 타인과 비교하지 않습니다.
- **3대 핵심 지표**: ① 외출 횟수(주 N번), ② 밤 운전(전조등 점등 기반, 10번 중 N번), ③ 다니는 거리(집 기준 정차 지점 평균 km).
- **엄격한 판정**: 기준선 대비 30% 넘게 줄어든 지표가 2개 이상인 상태가 '56일 중 49일 이상' 이어질 때만 자녀에게 요약을 1회 보냅니다(12주 쿨다운). 단발성 컨디션 난조로 인한 오경보를 줄입니다.

### 2) 정차 맥락 기반 제안형 귀가 안내 (급성 채널)

- **이탈 감지**: 지난 28일 평소 경로와 비교해 최근 15분 중 1km 이상 벗어난 시간이 10분 이상, 한 트립 재탐색 3회 이상, 같은 구역을 3분 이상 맴돎 중 하나면 이탈 후보로 봅니다.
- **정차 시에만 질문**: 주차 브레이크 체결 또는 P단 상태에서만 화면과 음성(TTS)으로 "어디 가시나요? 집으로 안내할까요?"라고 묻습니다.
- **원터치·음성 실행**: "집" 또는 "응/그래"라고 답하거나 버튼을 누르면 순정 내비게이션(NaviHelper SDK)으로 집 안내를 시작합니다.
- **30일 2건 누적 시에만 알림**: 1회성 이탈은 차 안 안내만 하고, 30일 안에 서로 다른 날 2건이 쌓일 때만 자녀에게 길 헤맴 알림을 보냅니다.

### 3) 신호별 대화 코칭 (원인 분리, 낙인 방지)

- **활동량 감소(만성)**: 우울·관절·시력·자발적 방어운전 가능성을 고려해 "요즘 컨디션 어떠세요? 종합 건강검진 같이 가요" 가이드와 종합 건강검진을 안내합니다.
- **반복된 길 헤맴(급성)**: "요즘 길 찾기 어떠세요?" 가이드와 가까운 치매안심센터 무료 인지선별검사(CIST)를 안내합니다.
- 앱은 진단하지 않고 권유만 합니다.

### 4) 모바일 앱으로 대체하기 어려운 차량 특화 요소

- **운전자 귀속**: 스마트폰은 동승과 운전을 구분하기 어렵습니다. 차량은 부모 차의 운행만 기록하고, 조작 패턴(마할라노비스 거리) 필터로 다른 가족의 운전을 일부 걸러냅니다(습관 차이가 클 때).
- **정차 맥락 보장**: 스마트폰은 신호 대기와 완전 정차를 구분하기 어렵지만 차량은 P단·주차 브레이크 신호를 알 수 있어, 완전 정차 때만 묻고 출발하면 즉시 화면을 닫아 운전자 주의분산을 줄입니다.
- **내비게이션 직접 실행**: 별도 앱 조작 없이 음성 한마디로 순정 내비 목적지를 집으로 설정합니다.
- **부모 주권과 투명성**: 부모는 차량 화면에서 "이번 달 자녀에게 공유된 내용"을 언제든 보고, 음성("공유 멈춰줘")이나 화면으로 공유를 멈추며, 연결 해제·기록 삭제를 할 수 있습니다.
- 한계: 만성 지표 자체는 휴대폰으로도 계산할 수 있어, 차량의 가치는 운전자 귀속·정차 맥락·내비 실행에 있다고 봅니다.

## 4. 주요 사용 시나리오

**시나리오 1: 최초 연동과 부모 동의 (정차 중)**
1. 자녀가 모바일 앱을 무료로 설치하고, 부모 차량에서 CareDrive(Pleos App Market 월 3,900원)를 실행합니다.
2. 차량 화면(V-000)에 6자리 일회용 연결 코드(예: 842-195)가 표시됩니다.
3. 자녀가 코드를 입력해 연결을 요청하면, 차량이 정차(P단)했을 때 수락 화면(V-001)이 뜹니다.
4. 부모가 "평소 운전 패턴(횟수·시간대·이동 범위)이 달라지면 자녀분께 요약해서 알려드려요. 실시간 위치는 보내지 않아요. 언제든 끌 수 있어요" 문구를 확인하고 [동의하고 연결하기]를 누릅니다.
5. 28일·20회 기준선 학습이 시작되고, 자녀 앱 홈에 학습 진행률이 표시됩니다.

**시나리오 2: 급성 이탈 시 정차 음성 안내와 내비 귀가**
1. 부모가 익숙한 시장에서 돌아오는 길에 경로를 벗어나 15분 이상 맴돕니다.
2. 변속기를 P단에 놓자 차량 화면(V-020)과 음성이 나옵니다. "어디 가시나요? 집으로 안내할까요?"
3. 부모가 "응, 집으로 가자"라고 말합니다.
4. 차량이 순정 내비 목적지를 집으로 설정하고 안내를 시작합니다(V-021).
5. '길 헤맴 후보 1건'이 조용히 기록되며, 1회성이므로 자녀에게는 알림이 가지 않습니다.
6. 3주 뒤 다른 날 같은 일이 한 번 더 있어 30일 안에 2건이 쌓이면, 자녀 폰에 길 헤맴 알림(C-052)과 치매안심센터 인지선별검사 안내(C-040B)가 도착해 자연스러운 대화가 시작됩니다.

**시나리오 3: 활동량 감소 감지와 건강검진 연계**
1. 예를 들어 부모의 무릎이 불편해져 주 4~5회이던 외출이 주 1회로 줄고 밤 운전을 피하게 됩니다.
2. 외출 횟수와 밤 운전이 기준선 대비 크게 줄어든 상태가 56일 중 49일 이상 이어집니다.
3. 자녀 앱으로 활동 감소 요약 알림(C-031)이 옵니다.
4. 자녀는 지도나 위치가 아니라 '활동량과 생활 반경 변화'를 보고, 코칭(C-040A)의 대화 예시로 면허 반납 이야기 없이 종합 건강검진을 권합니다.

**시나리오 4: 부모의 확인과 통제**
1. 부모는 주차 후 차량 화면(V-004)에서 "최근 평소와 다른 운전 패턴(외출·밤 운전 감소)이 이어지고 있다고 알려드렸어요. 건강 점검 안내도 함께 전달됐어요"처럼 자녀에게 간 내용을 그대로 확인합니다.
2. 여행 중에는 "공유 멈춰줘"라고 말해 공유를 멈춥니다.
3. 정차 중 설정(V-005)에서 확인 한 번으로 연결을 끊고 차량·서버 기록을 모두 지울 수 있습니다.

## 5. 개발 계획

### 1) 시스템 구성

- **차량 앱**: Pleos Connect(Android Automotive, 에뮬레이터 2.1.0 기준 API 34, minSdk 28) 대상 Kotlin 앱. 판정 엔진(Kotlin)과 차량 화면(V-000 ~ V-021)으로 구성하며, 현재 차량 화면은 WebView로 구현해 호스팅한다.
- **온디바이스 데이터 처리**: 시동 OFF 시점에 하루 요약 지표를 만들고 원시 GPS·센서 데이터는 즉시 폐기한다. 서버에는 요약 지표와 이벤트 여부만 보낸다.
- **서버와 자녀 앱**: 하루 요약 동기화, 판정 결과 알림 중계, 자녀 앱 화면(C-001 ~ C-078). 현재 Vercel + Postgres로 동작한다. 차량 앱 결제는 Pleos App Market이 처리하고, 푸시 알림은 향후 추가한다(현재는 앱 안 알림 목록).

### 2) Pleos Connect SDK 활용 계획 (SDK 5종, API 13개)

- **Vehicle SDK**: Odometer(트립 수·주행 거리), Brake·AAOS Car API 속도(정차 확정과 시동 ON/OFF 기반 트립), Light(야간 비율), Steeringwheel·Safety·TurnSignal(알림 조건이 아닌 기록·타인 운전 필터).
- **NaviHelper SDK**: getBookmarkInfo·getRecentDestinationInfo(집·자주 가는 곳), getRouteStateInfo·getTBTInfo(경로 이탈 감지), requestRoute(수락 시 집 안내, 경로 옵션은 에뮬레이터에서 확인).
- **TextToSpeech·SpeechToText SDK**: 정차 시 질문 음성 출력과 응답 수신(ON_DEVICE 우선). 응답 분류는 LLM 없이 Kotlin 규칙 분류기(`classify()`)로 처리한다: 수락("집", "응", "그래"), 거절("아니", "괜찮아"), 목적지 발화, 무응답(15초).
- **FusedLocation SDK**: 이동 반경과 이탈 감지(권한 FUSED_LOCATION, NAVI_ROUTE, NAVI_ROUTE_SEARCH).
- 현재 이 SDK 연동은 시뮬레이션 입력으로 대신하고 있으며, 공개된 개발 문서 범위에서 Pleos Connect 에뮬레이터에 연동할 계획이다.

### 3) 검증 현황

- **구현**: 만성·급성 판정 엔진, 음성 응답 분류기, 데이터 파이프라인(Kotlin), 서버·DB, 자녀 앱·차량 화면(와이어프레임 기준).
- **유닛 테스트**: Kotlin 단위 테스트 39개 통과.
- **합성 데이터 시뮬레이션** (가상 고령 운전자 300명, 1년. 동작·오경보 통제 확인용이며 실제 성능 입증이 아님):
  - 정상 운전자 오경보: 연 0.04회
  - 기준선 대비 40% 감소 탐지율 85% (중앙 지연 10주), 30% 감소 61%
  - 길 잃고 맴도는 급성 상황 탐지율 99% (중앙 10.3분)
  - 타인 운전 3σ 혼입 시 필터로 탐지 성능 68% 복원
  - 10~15% 같은 작은 감소는 의도적으로 대부분 놓친다(8~17%만 탐지).
- **구동 확인**: Android 에뮬레이터(Medium Desktop, API 34)에서 차량 앱 구동·서버 연결·연결 코드 발급 확인. Pleos Connect Emulator는 2차 PT 전에 검증한다.

### 4) 단계별 로드맵

- **현재(1차 접수)**: 핵심 로직·화면·서버 구현, 테스트 통과, 시연 패널로 급성·만성 시나리오 재생.
- **2차 PT 전**: Pleos Connect 에뮬레이터에서 P단 변속, 정차 질문(TTS), 음성 수락(STT), requestRoute 집 안내까지 연동해 시연.
- **출시 단계**: Pleos App Market 정식 심사 통과, 지자체 치매안심센터 공공 정보 연계.

## 6. 기대효과 및 발전 가능성

### 1) 사용자·사회적 가치

- **고령 운전자**: 이동권을 빼앗기지 않고, 실시간 감시 없이 존엄하게 운전하며, 길을 헤맬 때 차량의 도움을 받습니다.
- **보호자(자녀 세대)**: "면허 반납하라"는 대립 대신, 객관적 변화 요약과 신호별 대화 코칭으로 건강검진·선별검사를 권할 수 있습니다.
- **기대 효과(검증 필요)**: 정기 검사 사이에 생긴 큰 변화를 가족이 알아차려 검진으로 이어지면, 늦게 발견되는 일을 줄이는 데 기여할 수 있습니다. 이 앱은 진단이나 조기 탐지 도구가 아니라 큰 변화를 놓치지 않게 하는 안전망입니다.

### 2) 비즈니스 모델 (차량 유료 구독 + 자녀 100% 무료)

- **과금**: 부모 차량의 Pleos App Market에서 차량 앱 유료 결제(월 3,900원 기준안, 무료 체험 없음), 자녀 모바일 앱은 100% 무료(무제한 연동).
- **당위성**: 자녀 앱에 결제 허들을 두면 설치와 가족 연동이 줄어듭니다. 결제를 차량에 두고 자녀를 무료로 하면 연동률을 높이면서, 대화면·센서·순정 내비 연동이라는 차량 고유 가치에 대한 지불 명분이 생깁니다.
- **시장 규모(가정)**: 65세 이상 면허 소지자 517만 명 × Pleos Connect 탑재 차량 보유율 3% × 유료 전환율 3% → 1년 차 약 4,650대, 연 매출 약 2.2억 원(3,900원 기준, 유지율 반영 전). 가격·전환율은 가정이며 인터뷰·설문으로 검증합니다.

### 3) 핵심 지표 (KPI)

- 자녀 초대 후 부모 수락률 60% 이상, 28일 기준선 완성률 80% 이상
- 유료 구독 3개월 유지율 70% 이상
- 오경보 피드백률 10% 이하, 알림 후 검진 완료 입력 전환율 30%

### 4) 현대자동차그룹·Pleos 생태계 기여

- 차량 내부 센서와 순정 내비를 결합한 차량 전용 소프트웨어 사례를 제시합니다.
- 고령 부모(차주)와 4050 자녀 세대를 한 서비스로 연결해 가족 단위로 생태계에 묶습니다.

### 5) 향후 확장

- **ADAS 연계**: 향후 ADAS SDK가 공개되면 차선·차간 거리·급제동 같은 안전 지표를 단계적으로 추가할 계획입니다.
- **공공·보험 연계(가설)**: 부모의 별도 동의를 전제로 지자체 치매 예방 사업 연계와 안전운전 데이터 기반 보험 상품을 검토합니다.
- **대상 확장**: 장거리 야간 운전자 피로 케어, 초보 운전자 가족 안심 케어로 넓힐 수 있습니다.
